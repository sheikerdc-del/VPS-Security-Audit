# VPS Security Audit 🔐

**Read-only аудит безопасности Linux VPS**

`vps-audit.sh` — автономный Bash-скрипт для первичной проверки VPS на признаки компрометации, подозрительную активность, несанкционированные SSH-доступы, persistence-механизмы, подозрительные процессы и сетевые соединения.

Скрипт предназначен прежде всего для **Ubuntu / Debian VPS** и не требует установки дополнительных пакетов.

> ⚠️ Это инструмент первичной диагностики, а не полноценная forensic-система. Отсутствие найденных проблем не является гарантией того, что сервер не был скомпрометирован.

---

## Возможности

Скрипт выполняет read-only проверки следующих областей:

### 🔑 SSH

* успешные SSH-входы;
* неудачные попытки авторизации;
* попытки входа под `root`;
* неизвестные пользователи;
* `authorized_keys`;
* настройки `PermitRootLogin`;
* `PasswordAuthentication`;
* активные SSH-сессии;
* IP-адреса, с которых выполнялись попытки входа.

### 👤 Пользователи

* пользователи с shell-доступом;
* UID `0`;
* пользователи в `sudo` / `wheel`;
* потенциально подозрительные административные аккаунты.

### 🌐 Сеть

* открытые listening-порты;
* активные TCP/UDP-соединения;
* процессы, использующие сеть;
* сетевые интерфейсы;
* маршруты;
* DNS;
* firewall;
* подозрительные proxy/tunnel-инструменты.

### ⚙️ Процессы

* процессы с максимальным CPU;
* процессы с максимальным использованием RAM;
* дерево процессов;
* executable из:

  * `/tmp`;
  * `/var/tmp`;
  * `/dev/shm`;
* признаки reverse shell;
* подозрительные сетевые инструменты;
* возможные crypto-miner процессы.

### 🧩 Persistence

Проверяются:

* `cron`;
* пользовательские crontab;
* `/etc/cron.*`;
* systemd services;
* недавно изменённые systemd unit-файлы;
* shell profiles;
* SSH keys;
* `sudoers`;
* `/etc/ld.so.preload`.

### 🐳 Docker

Если Docker установлен:

* контейнеры;
* остановленные контейнеры;
* Docker images;
* networks;
* `docker.sock`;
* privileged containers.

### 📁 Файловая система

Проверяются:

* недавно изменённые файлы;
* SUID/SGID;
* world-writable файлы;
* `/tmp`;
* `/var/tmp`;
* `/dev/shm`;
* `/root`;
* подозрительные executable-файлы.

### 🛡️ Системная безопасность

Проверяются:

* UFW;
* nftables;
* iptables;
* Fail2ban;
* auditd;
* kernel warnings;
* system errors;
* failed systemd services;
* история APT;
* kernel modules.

# Установка

Установка не требуется.

Скачать файл:

```bash
git clone https://github.com/YOUR_USERNAME/vps-security-audit.git
cd vps-security-audit
```

Сделать исполняемым:

```bash
chmod +x vps-audit.sh
```

---

# Запуск

Рекомендуется запускать от `root`, чтобы получить максимально полный результат:

```bash
sudo ./vps-audit.sh
```

Или:

```bash
sudo bash vps-audit.sh
```

---

# Сохранение отчёта

Для сохранения результата в файл:

```bash
sudo ./vps-audit.sh | tee "vps-audit-$(date +%F-%H%M).log"
```

После выполнения появится файл примерно:

```text
vps-audit-2026-08-14-1135.log
```

Это удобно для последующего анализа или передачи специалисту.

# Уровни результатов

В конце аудита отображается сводка:

```text
OK        : 42
WARNING   : 7
CRITICAL  : 1
```

## 🟢 OK

Проверка не выявила очевидной проблемы.

Пример:

```text
[OK] Прямой root SSH login не разрешён явно.
```

---

## 🟡 WARNING

Обнаружен фактор, который **может быть нормальным**, но требует ручной проверки.

Например:

```text
[WARNING] PasswordAuthentication yes.
```

Это не обязательно означает взлом.

Например, сервер может быть намеренно настроен на вход по паролю.

---

## 🔴 CRITICAL

Обнаружен признак, который требует немедленного расследования.

Например:

```text
[CRITICAL] Обнаружен работающий executable из /tmp.
```

или:

```text
[CRITICAL] Обнаружены процессы с признаками reverse shell.
```

`CRITICAL` не означает автоматически «сервер взломан».

Это означает:

> **обнаружен признак, который нельзя игнорировать.**

---

# Что делать при CRITICAL

Если аудит показал:

```text
CRITICAL > 0
```

**не следует сразу удалять найденный файл или убивать процесс.**

Сначала рекомендуется:

1. Сохранить полный лог аудита.
2. Зафиксировать IP-адреса и процессы.
3. Проверить SSH-входы.
4. Проверить `authorized_keys`.
5. Проверить cron.
6. Проверить systemd.
7. Проверить Docker.
8. Проверить сетевые соединения.
9. Снять snapshot VPS, если это поддерживает ваш провайдер.
10. Только после этого приступать к remediation.

# Важный принцип

Скрипт является **read-only**.

Он:

* ❌ не устанавливает пакеты;
* ❌ не удаляет файлы;
* ❌ не отключает пользователей;
* ❌ не блокирует IP;
* ❌ не меняет firewall;
* ❌ не меняет SSH;
* ❌ не убивает процессы;
* ❌ не перезапускает сервисы;
* ❌ не изменяет Docker;
* ❌ не исправляет найденные проблемы.

Он только собирает информацию и анализирует её.

Это сделано специально.

Автоматическое исправление при подозрении на взлом может:

* уничтожить forensic-свидетельства;
* скрыть способ проникновения;
* сломать работающие сервисы;
* удалить легитимный файл;
* нарушить конфигурацию VPS.

# Что скрипт НЕ может гарантировать

Даже если результат:

```text
OK: явных признаков компрометации не обнаружено
```

это **не означает 100% отсутствие взлома**.

Особенно это относится к ситуации, когда атакующий получил `root`.

Если на сервере присутствует rootkit или были изменены системные бинарники, обычные команды Linux могут показывать недостоверную информацию.

Для полноценного forensic-анализа рекомендуется:

1. сделать snapshot диска;
2. остановить скомпрометированный VPS при необходимости;
3. подключить диск к доверенной системе;
4. анализировать файловую систему извне;
5. сравнить системные файлы с эталонными пакетами;
6. проверить persistence и сетевую активность.

# Требования

Минимальные требования:

* Linux;
* Bash;
* `procfs`;
* `systemd` — желательно;
* root-доступ — рекомендуется.

Дополнительные инструменты используются только если они уже установлены.

Например:

```text
docker
lsof
pstree
ufw
nft
iptables
fail2ban
auditctl
rkhunter
chkrootkit
```

Скрипт **не устанавливает отсутствующие инструменты автоматически**.

# Безопасность

Скрипт не передаёт результаты аудита на внешний сервер.

Не используется:

* telemetry;
* analytics;
* внешний API;
* cloud backend;
* сторонний сервер;
* автоматическая отправка отчёта.

Все результаты выводятся локально в терминал.

# Ограничения

Это **не IDS, не EDR и не полноценная SIEM-система**.

Скрипт не выполняет:

* memory forensics;
* анализ сетевого трафика PCAP;
* полноценную проверку rootkit;
* криптографическую верификацию всех системных бинарников;
* анализ диска с внешней доверенной ОС;
* поведенческий анализ процессов;
* корреляцию событий между несколькими серверами.

Его задача — быстро ответить на вопрос:

> **«Есть ли на VPS очевидные признаки компрометации, которые требуют расследования?»**
